021回の生成で流れる JSON-RPC シーケンス

codex-cli 0.136.0 で検証済みのプロトコル。ハンドシェイクは初回のみ、生成のたびに thread/start から新しい使い捨てスレッドを切る。

  1. initializerequest

    clientInfo（voq-mail）と experimentalApi: true を送り、v2 の thread/turn メソッドを有効化。初回1度だけ。

  2. account/readrequest

    サインイン済みアカウントを確認。account が無ければ notAuthenticated を投げて生成中止。

  3. thread/startrequest

    新しいスレッドを開始。sandbox: "read-only" / approvalPolicy: "never" / ephemeral: true、cwd は一時ディレクトリ。ここで developerInstructions（システム役割）を渡す。

    → 返ってきた thread.id で active slot を設置（最初の delta を取りこぼさないよう turn/start の前に）

  4. turn/startrequest

    ユーザー入力として prompt（宛先・件名・元メッセージ・既存下書き・指示）を 1つの text input で送信。turn.id を控える。

  5. item/agentMessage/deltanotification ×N

    本文がトークン断片で次々と届く。reader が threadId で照合し、active な continuation に yield(delta) → Store が draftText.append → プレビューに即反映。

  6. turn/completednotification

    ターン終了。continuation を finish() し、active slot をクリア。error 通知なら turnFailed で終わる。

03codex に渡す2つのプロンプト

「役割の固定指示」と「毎回の文脈」を分離。前者は thread/start の developerInstructions、後者は turn/start の input。

developerInstructions（役割・固定）

// thread/start に同梱 You are VoqMail's reply-drafting assistant... Rules: - 本文テキストのみ出力 （件名/markdown/引用符なし） - 元メッセージを引用し返さない （ヘッダでスレッド化される） - 会話と同じ言語で書く （多くは日本語・敬語を選ぶ） - 指示に厳密に従い、文脈に 無い事実を捏造しない - そのまま送れる文面にする

prompt（毎回の文脈）

// turn/start の input.text To: {宛先} Subject: {件名} 返信対象の本文（文脈のみ・ 引用し返さない）: """{元メッセージ}""" ユーザーが既に書いた下書き: """{下書き or (empty)}""" どう書くかの指示: {instruction} Write the final email body now.

狙い：元メッセージと既存下書きを 読み取り専用の文脈として渡すことで、モデルが事実を捏造せず根拠のある返信を書けるようにしている。出力は本文だけなので、そのままコンポーザーに差し込める。

04取りこぼし・競合・ハングを防ぐ仕掛け

actor は await ごとに割り込むので、Regenerate 連打でも古い実行が現在の状態を踏まないよう多重に守られている。

✓世代カウンタ（2層）

Store の generation と actor の latestStreamID / activeStreamID。各 await 後の書き込み前に「まだ自分が最新か」を確認し、超過した実行の delta や末尾の isGenerating=false を無効化。

✓キャンセル＝turn 中断

ストリーム終了（onTermination）で turn/interrupt を送り課金を止める。turn.id 未確定の中断は interruptPendingThreadIDs に積んで、id 到着後に処理。

✓タイムアウト2種

request は 30秒、turn は 120秒の上限。生きたままハングした子プロセスが UI を永久に「生成中」に縛らないよう、強制的に finish。

✓ブロッキング読みを隔離

stdout の blocking read は専用 GCD キューで実行し、AsyncStream で actor 側へ。actor の executor を塞いで runGeneration とデッドロックするのを回避。

✓承認要求は即拒否

read-only で承認オフのため本来来ないが、id+method を持つサーバ発リクエストは -32601 で防御的に拒否し、サーバが待ち続けないようにする。

✓切断時に全 waiter を解放

子プロセスが EOF（終了）したら pending・login・active の全 continuation を失敗させ、呼び出し側がハングしない。

05その前提：バイナリ発見とサインイン

codex は ~187MB あるためバンドルせず、システムの既存インストールを検出する BYO 方式。

CodexLocator：Finder 起動の .app はシェル PATH を継承しないので、まず絶対パス候補（~/.local/bin、Homebrew、cargo…）を当たり、無ければ $SHELL -lc 'command -v codex' でログインシェルに解決させる。--version を読み 0.125.0 以上を要求する。

サインイン：codex 未ログインなら account/login/start（type=chatgpt）で authUrl を取得 → ブラウザを開く → codex がローカルコールバックを受け、account/login/completed 通知を loginId で待ち受けて完了。可用性は再チェックされ ready になる。
